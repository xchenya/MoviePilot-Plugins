# 思齐自动收垃圾（SiQiCleanBeach）

本插件是 [bfjy2024/MoviePilot-Plugins](https://github.com/bfjy2024/MoviePilot-Plugins/tree/main/plugins.v2/siqicleanbeach)
中 V2 插件「思齐自动收垃圾」的 **MoviePilot V3 移植版**。

- 原作者：bfjy；V3 适配维护：xchenya。
- 插件版本：**2.3.0**；宿主要求：**MoviePilot >= 3.0.0**。
- 功能：自动进入沙滩、收集垃圾，可选自动搬砖；完整展示含砖块的库存，分别记录清理和搬砖结果、近 20 次历史及通知。
- 调度方式：支持按站点冷却或固定时间（5 段 Cron），保留旧固定分钟间隔；支持保存配置后运行一次、/siqi_clean_beach 命令和带认证的手动运行 API。

## 安装

在 MoviePilot V3 中将 https://github.com/xchenya/MoviePilot-Plugins 加入第三方插件市场，刷新插件列表并找到「思齐自动收垃圾」。

配置「启用插件」、定时模式和通知。**Cookie 留空时会从 MoviePilot 站点管理读取域名 si-qi.xyz 的 Cookie**；也可以自行填写包含 c_secure_pass 的 Cookie。不要把 Cookie 粘贴到 Issue、截图、日志或公开配置中。

新安装默认选择「按站点冷却」；旧配置的定时模式保持不变。旧版固定间隔用户需改选「按站点冷却」才能使用到期调度。关闭定时开关不影响手动运行。

### 调度方式（二选一）

1. **按站点冷却（推荐）**：清理和搬砖独立保存到期时间，使用本地一次性任务等待较早的一项，到期执行后再安排下一次；等待期间不访问站点、不写历史或发通知。首次启用或从旧调度升级时，约15秒后只读同步沙滩时间，搬砖先查询状态，符合条件才执行。沙滩使用页面 `gameData` 的 `lastBeachTime`、`beachInterval` 和服务端时刻计算两小时冷却；搬砖满50块后使用 `next_brick_reset_ts - server_now` 安排站点次日零点。统一留15秒余量，正常运行时目标在冷却到期后5分钟内启动，不再受10/60分钟检查间隔影响。
2. **固定时间（Cron）**：按宿主时区运行。例如 `5 0 * * *` 表示每天 00:05；`5 */2 * * *` 表示每两小时的第 5 分钟。触发时仍核对站点每日上限和沙滩冷却，不能强制绕过站点限制。

表单保留「旧版固定间隔」作兼容，`interval_minutes` 仍控制该模式的任务周期。所有模式的搬砖均按服务端每日50块及零点重置判断，不再等待上次搬砖后完整24小时；旧 `brick_cooldown_minutes` 和 `check_interval_minutes` 配置可读取但不再生效，保存时移除，不影响自动搬砖开关、库存及历史。

每轮获取库存页面时同步沙滩时间。网页的两小时冷却从进入沙滩成功开始；若后续库存页面读取失败，以已确认的进入时间加两小时安排，库存仍如实标注缓存。首次同步缺字段时只重查页面，不盲目进入沙滩。同步或执行失败按5、15、30、60分钟退避重查，最多每小时一次；确认Cookie失效后暂停自动任务，更新配置或手动验证成功后恢复。写入超时仍先核对状态，不盲目重试。

升级时仅使旧调度缓存失效一次，保留历史、库存和不确定写入保护。新到期时间会保存，重启后恢复；已过期的约15秒后补执行一轮，不补跑停机期间的每个周期。5分钟目标针对宿主正常运行时的任务启动，站点/网络故障、长请求、宿主停机或严重时钟跳变可能使其超出；完成50块的耗时另计。

停止服务或运行中重载配置会阻断后续请求（已经发出的请求无法撤回），已排队的定时任务也不会在关闭后重新启动。运行中重载保留当前统计、库存和安全标记，避免旧表单数据覆盖最新进展。重置等待从状态响应接收时计算，不叠加后续库存查询耗时；非有限值或超出日期范围的缓存重新同步，超出 48 小时的每日重置间隔按异常处理。

面板定时模式简写为「按站点冷却」，沙滩/搬砖的「下次执行时间」只显示到分钟（如 `2026-10-15 18:15`），最后结果仅显示清理和搬砖消息。自动模式通知同样显示到分钟，统计和历史保留完整数据。其他设备手动操作将在到期查询时同步，服务端冷却仍优先。

清理完成、另一项正常等待或已达每日上限时显示「全部完成」；自动任务确认两项都在等待时只更新缓存，不新增历史或通知。真正的业务失败、认证失败、超时或异常仍如实报告，不能用「全部完成」掩盖错误。

### 自动搬砖

「自动搬砖」独立开关默认关闭，旧配置不自动开启。开启后复用现有Cookie、运行入口及实例锁。站点规则是每天最多 **50块**，以服务端零点重置为准，取消本地1440分钟限制。

收集垃圾优先解析当前前端使用的 `collected_items` 物品数量表，兼容旧 `collected` 数量字段及明确的收集数量消息。仅在JSON明确业务成功时计为成功；没有可靠数量则显示「收集成功（数量未知）」，不改判失败，也不用库存差值或消息中的任意数字猜数量。

- 搬砖前 POST `action=sync_game_state`，读取每日数量及服务端重置时间；上限 50，已达上限正常跳过，不用本机日期重置计数。
- 每轮 GET/POST 共用一个 HTTP Session 复用连接池和响应 Cookie，任务结束关闭，不跨任务或实例共享。使用相同浏览器 User-Agent，优先采用站点管理的 UA，没有时回退原插件浏览器 UA。请求连接超时 10 秒、读取超时 30 秒；状态查询超时后间隔 2 秒最多重查一次，游戏写入不重试。状态同步连续超时会明确报告“未发送搬砖请求”。日志记录动作名、HTTP 状态、耗时、异常类型及校验通过的搬砖增量，不记录 Cookie。
- POST `action=move_brick`，按 `bricks_moved` 和 `daily_bricks` 校验增量，不假定每次搬多少。最多 50 次，串行间隔 2 秒；失败、无进展、字段异常或跨日立即停止。
- 搬砖超时后先同步状态，若同一服务端日的数量增加，用同步差值记录已观察到的进展，并标记 `recovered_from_sync`；差值不能排除用户同时手动搬砖的影响。无论同步结果如何，本轮停止、不重试。结果不确定时持久化保护，等待服务端下一次每日重置后才允许再次写入；重置前仍可查询状态。
- 沙滩冷却或普通业务失败不阻止搬砖；认证失败阻断后续请求。HTTP 403 保守按认证/访问拒绝处理。写请求不跟随重定向，只接受有布尔 `success` 的 JSON，不按 HTML 中“成功”判断。
- 库存刷新失败保留缓存，明确标识“缓存，非本次刷新”，不推进库存刷新时间；本次搬砖数、今日数量、砖块库存分别展示。今日状态未知时显示未知。
- 库存条目缺字段、数量无效或重名时，整轮库存保留缓存，不把未知数量当作 0，也不以部分数据覆盖完整库存。

没有自动炼造、赠送或魔丸兑换功能。

## API 与命令

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | /api/v1/plugin/SiQiCleanBeach/run | 后台启动一次收集任务 |
| GET | /api/v1/plugin/SiQiCleanBeach/stats | 获取执行记录与库存缓存 |

以上 API 均使用 MoviePilot 的 Bearer 鉴权，页面不包含独立公开操作链接。详情页展示已缓存的数据，任务结束后重新打开/刷新详情页可查看最新结果。

## V3 改动

- 换用 V3 原生 app.sdk.events、app.sdk.logging，以及宿主正式的 app.db.oper.site.SiteOper。
- 每个插件实例独立持有运行锁、历史和库存，避免分身或重载时状态交叉。
- 手动执行先抢占运行锁，再启动后台线程，防止并发重复启动。
- 所有 HTTPS 请求启用证书校验，不再全局关闭 urllib3 证书警告。
- 用 BeautifulSoup 解析完整库存 DOM（包含「砖块」），保留站点 HTML 结构变化时的历史缓存。
- 保存失败、Cookie 失效等执行结果；声明 V3 API 返回模型。

## 注意事项与测试状态

**当前为 V3 兼容性测试版。用户2026-10-15的宿主日志确认此前已搬满50块并刷新库存；2.3.0到期调度及收集解析修订未经宿主联调。** 原站点网页和接口可能变化，若收集动作失败，应检查站点登录状态及HTML/JSON响应。为安全考虑，不会自动忽略失效的HTTPS证书。

已提供不访问真实站点的解析、Cookie、安全、并发、搬砖、冷却调度及配置持久化Mock测试，以及真实APScheduler本地回调与重新排期测试（HTTP仍全部Mock）。2026-10-16仅只读核验已登录网页的收集前端和冷却初始化脚本，确认 `collected_items`、进入沙滩计时及7200秒间隔；未触发真实搬砖或收垃圾。已有不确定写入保护不会因升级自动清除。市场条目保留 `release: false`。

离线验证：`python -m pytest tests/v3/siqicleanbeach -q`。搬砖状态或时间字段异常时停止写入；收集数量未知则单独标注，不猜测服务端状态。
