# 憨憨保种区管家（MoviePilot 插件）

<img src="https://github.com/SixOrg.png" width="48" height="48" align="left" style="border-radius:50%;margin-right:10px;" alt="六个橙子" />

作者：**六个橙子**（[GitHub](https://github.com/SixOrg)）

## 功能

- **自动抓取憨憨保种区（rescue.php）全部种子**
- **增量优选**：不删除已有保种任务，按目标体积自动补齐缺量种子
- **换种优选（删低档位&补高档位）**：删除低档位种子、补充高档位种子（跨档位升级）
- **档位策略**：按初始做种人数分档（0-1人 / 2-3人 / 4-5人），高倍率替换低倍率
- **自动清理未完成下载**：可设置 N 天，自动删除超时仍未完成的本站下载任务
- **保种管理器**：独立网页工作台，支持批量删除、搜索、档位筛选、列自定义、多皮肤切换
- **站点∩下载器交叉匹配**：确保只操作真实在保种子
- **上次憨豆/上次积分展示**：面板显示 0 点结算的收益结果
- **数据面板**：当前保种数量/总体积/目标体积/各档位分布，每 6 小时自动刷新（顺带拉取并保存当日结算日志，两处憨豆/积分同源一致）
- **结算统计表**：独立页面展示近 30 日憨豆/积分实结柱状图、累计憨豆/积分左右双环仪表、近 12 月逐月实结滚动明细，翻页拉取结算日志并本地累计，每日仅拉取一次
- **Hosts 加速**：开启并配置 IP 域名（每行一条）后写入系统 hosts，加速憨憨站或需要加速的其他站点；关闭开关或清空配置自动还原；错误条目不写入（参考 thsrite「自定义Hosts」插件，见文末致谢）
- **消息推送**：运行完成推送在保数量、各档位分布及上次结算憨豆/积分

## 安装（GitHub 插件市场）

1. 打开 MoviePilot Web UI → 「设置」→ 插件市场 → **添加仓库**，填入：

   ```
   https://github.com/xchenya/MoviePilot-Plugins
   ```

2. 进入「插件」页面 → 刷新插件市场 → 找到「憨憨保种区管家」→ 安装并启用。

## 站点信息（全自动，无需手动配置）

插件从 MoviePilot「设置 - 站点」自动读取憨憨站的 Cookie / UA / 站点地址（按域名匹配 hhanclub / hhclub），并自动访问站点主页解析站点 UID。只要在 MP 站点管理里添加过憨憨站，无需任何手动配置，UID 自动获取。

若自动获取失败（站点 Cookie 过期、站点主页不可达等），插件会停止运行并在日志提示——请检查 MP 站点管理里憨憨站的 Cookie/UA 是否有效，更新后重新运行即可。

## 配置说明

| 配置项 | 说明 |
|--------|------|
| 发送通知 | 勾选后每次运行完成推送结果（企微/Telegram/站内信等） |
| 优选模式 | 增量优选 / 换种优选（删低档位&补高档位） |
| 目标体积（GB） | 总保种体积目标，0=不限 |
| 管理下载器（多选） | 统计/优选/管理/删除覆盖所选下载器（可多选，支持 QB/TR 多容器混用） |
| 推送下载器（单选） | 新增任务的下载器，默认=管理下载器第一个 |
| 保存路径 | 推送下载器使用的保存目录，可填任意盘符路径（严格按此路径落盘，不再被下载器自动管理覆盖），留空用下载器默认 |
| 自动清理未完成下载（天） | 本站相关的未完成下载任务超过 N 天仍未完成时，自动删除任务+文件；0=不启用 |
| 执行周期 | cron 格式，默认每天定时运行 |
| Hosts 加速 | 开关 + 配置（IP 域名，每行一条）；开启并填写可加速站点（支持配置其他站）；关闭开关或清空配置自动还原；错误条目不写入 |

## 保种管理器

点击面板中的「保种管理器」按钮，新窗口打开独立工作台：

- 种子列表：ID、名称、大小、初始人数、当前人数、档位、完成时间、上次结算时间、今日做种时间、今日达标状态、来源下载器
- 表头点击排序、列宽拖拽、列显隐自定义（浏览器本地持久化）
- 搜索、档位筛选、批量删除（同步删除对应下载器任务及文件，按种子来源下载器定位）
- 多皮肤切换（下拉直达，设置本地持久化）
- 加载过程显示实时读秒与进度条提示


## 结算统计表

点击面板中的「结算统计表」按钮，新窗口打开独立页面：

- 近 12 个月每月憨豆 / 积分实结柱状图（数据标签与图形同色，来源：保种结算日志，每日 0 点实结）
- 累计憨豆 / 积分左右双环仪表（左环憨豆橙、右环积分青，中央显示累计数值）
- 近 30 日收益表：按结算日志逐日实结滚动明细
- 数据获取：概况每 6 小时刷新时顺带拉取并保存（每日一次，当日命中缓存后不再重复请求）；结算日志按时间正序分页，翻页全量拉取并按月聚合（最新一条取末页，兼容多页）；拉取失败或站点当日记录未生成时，每 5 分钟自动重试一次、当日累计最多 3 次，页面明确标注数据日期与获取状态；本地数据原子写入，杜绝空文件导致重复拉取
- 加载过程显示实时读秒与进度条提示

## 注意事项

- **换种优选会删除下载器中的任务并删除对应文件（释放硬盘空间）**，请确认后再启用
- 保种区每天下午 14:10 左右更新，建议执行周期设在更新之后
- MP 站点管理里的 Cookie 过期后，需在 MP「站点」页面更新
- 保种区规则：做种人数超过 5 的种子会被定期移出保种区
- Hosts 加速：容器部署更新的是容器内 /etc/hosts（非宿主机）；IP 填写错误会导致站点不可达，请谨慎填写；卸载插件前建议先关闭 Hosts 加速开关以便自动还原

- 手动删除强制同时核对站点在保记录、下载器名称、精确种子哈希和 Tracker，并要求明确确认；无法精确匹配则拒绝删除。

## V3.0.2 — 处理 Cloudflare 524 超时

- 保种管理器首次访问 /list_rescue_seeds 立即返回 loading=true，耗时的站点分页和下载器交叉匹配在插件进程内部的单个后台读取线程中完成。后续短请求轮询，不再要求 Cloudflare 在同一个 HTTP 请求内等待全部分页。
- 成功快照在进程内缓存 180 秒；刷新页面优先读取有效缓存，失败不缓存空种子列表。点击“重试”会请求重新抓取；超过 8 分钟提示检查日志。
- 同时打开多个页面只触发一次正在进行的抓取；插件重载后的旧抓取结果不会覆盖新配置下的数据。
- 插件详情页与仪表盘只读取概况缓存；手动刷新概况也在后台运行。两者不再因站点读取阻塞前端。
- 种子详细信息仅按精确规范化名称且不重复的下载器任务合并；匹配不唯一时不提供删除用哈希。
- 日志输出下载器读取、完成页获取与列表合并的阶段耗时，用于定位真实慢点。

**注意：** 该版本解决 HTTP 524 等待超时，不能代替站点或下载器连接修复。若后台长时间卡住请查看 MoviePilot 插件日志。尚未在真实 MoviePilot 实例联调，release=false 保持不变。没有主动执行换种或删除种子。

## V3.0.3 — 删除任务、手动刷新与确认弹窗

- 保种管理器顶部新增「刷新列表」按钮：强制读取站点完成页与下载器实时种子列表，不依赖之前的 180 秒缓存。
- 删除请求现在只创建一个由 request_id 标识的后台任务，前端用 GET 状态接口查询排队/执行/已验证/失败/不确定状态。首次提交超时只查询既有任务，不会重新发送删除 POST。
- 一次仅允许一个手动删除后台任务；同一个 request_id 重复到达时返回原结果，不能对另一个种子复用同一 ID。浏览器 sessionStorage 记录未完成任务，意外刷新后尝试恢复查询。
- 下载器的删除方法仅表示指令是否被接受。只有读取下载器任务列表并确认目标哈希已经不存在，才报告「已确认删除」；否则标记状态不确定，禁止自动重试。
- 删除结果已确认或不确定时失效进程内种子列表缓存，并刷新页面数据；真实空下载器不再退回展示站点的「全部已完成」项目。
- 原生 alert/confirm 已换成适配多皮肤的自定义确认对话框及非阻塞提示，支持真正的多行文字和移动端。对话框只用 textContent 插入种子标题，不执行标题 HTML。
- 本版本 **不触发自动删除**。真实用户数据操作前请注意：删除下载器任务和其文件不可由插件撤销。未在用户生产环境联调，release=false 不变。

- 自动优选及换种仍使用原有 `_get_current_seeding()` 真实交集，不用管理页面全量资格清单替代，避免触发错误的自动删除或新增下载。
- 如果部分正在做种的任务没有关联，请检查插件已选择的管理下载器和任务的真实名称 / Tracker。非唯一的近似结果不会自动强制绑定。
- 如果站点实际条数仍不一致，请比较 MoviePilot 日志中的「站点完成页 UID、预计页数、去重后记录」与站点个人完成页；插件自动识别 UID，不会在源码中写死账号。

## V3.0.5 — 修复大量下载器关联被误判为「有歧义」

- 修复 V3.0.4 的错误判据：旧算法把同一个下载任务在其他站点条目中的**近似匹配**算进反向冲突，甚至会让原本唯一、精确、已完成的 Transmission/qBittorrent 种子被标为「有歧义」。
- 采用两轮关联：第一轮先绑定规范化后的**精确名称**匹配，并保留所有权；第二轮仅用未被精确占用的任务做**近似关联**。近似关联只作展示，仍不允许删除文件。
- 同一个下载器、相同种子哈希和相同规范化标题若出现在返回列表多次，只计算一个任务；不同哈希或来自不同下载器的真实同名任务仍被判定为冲突，禁止自动选择删除对象。
- 「有歧义」悬浮说明现在区分：多个真实下载任务、站点同名记录、多个站点近似命中同一任务。插件日志只输出原因的计数，不写入 Cookie 或完整种子哈希。
- 注意管理页顶部「筛选下载器(1)」代表**当前筛选了一个下载器**，不是插件后台只配置一个下载器；可点击筛选框中的「清空」以查看全部。
- 修复针对列表关联算法，不改变站点资格总列表、后台轮询、自动优选、自动换种和删除安全检查。

本次已通过模拟场景及回归测试，但未使用真实站点 Cookie 或生产下载器验证。仍保持 `release=false`。如果更新后大量条目继续显示有歧义，请提供插件日志中的「歧义归因（仅计数）」一行，以区分真实重复任务和不同站点条目间的冲突。

## V3.0.6 — Transmission 中文译名前缀关联

- 典型问题：站点发布名 `A Lifetime Love S01 2017 1080p WEB-DL H264 AAC-HHWEB`，Transmission 任务名为 `上古情歌.A.Lifetime.Love.S01.2017.1080p.WEB-DL.H264.AAC-HHWEB`。V3.0.5 把汉字保留在规范化名称里，因此只能命中普通近似候选，还可能与同资源的不同版本产生歧义。
- 新增严格的「译名匹配」：只在下载器名称以独立中文译名前缀开头、去掉此前缀后剩余完整英文发布名与站点全名相同、双方均有可靠体积且差异不超过 1.5%（最小误差容限 0.05 GiB）时触发。不因相同文件大小就自动关联不同标题。
- 优先级调整为：**完整名称精确 → 中文译名 + 英文发布名强关联 → 普通近似匹配**。精确和译名匹配的任务不再被其它站点记录的普通近似候选占用，减少「有歧义」误报。
- 保种管理器新增“译名匹配（仅查看）”标签与数量统计。译名关联暂不开放删除按钮，因为后台删除仍要求完整种子名精确对应；不同下载器/哈希的实际重复任务依旧视为歧义。
- 日志新增译名关联数量，仅输出汇总，不记录站点 Cookie 或完整哈希；保留站点全部保种资格、后台抓取及自动优选的原有安全逻辑。

本版本已通过模拟名称、重复任务及回归测试，但没有在真实憨憨站与 Transmission 上验证；继续保留 `release=false`。

## V3.0.7 — 放宽中文译名确认与按 Tracker 核验手动删除

- 当 Transmission/qBittorrent 任务名带独立的中文译名前缀时，去掉前缀，对剩余的**完整英文发布名**按全角/半角、大小写、空格和标点统一规范化，必须与站点发布名完全一致；不使用松散的包含关系作为删除依据。
- **大小一致**改为允许最大约 `0.011 GiB` 的展示四舍五入偏差；旧版 `1.5%` 的容差不再用于中文译名确认。无可靠体积数据或者差异过大则无法确认。
- 名称和大小符合，即可显示为已关联的“译名匹配”；只有额外精确验证到下载器的 Tracker 主机名是 `tracker.hhanclub.net`、种子完成、哈希唯一且没有第二个下载器/站点记录歧义，才开放用户主动删除。相似域名或 Tracker 未验证仍只读。
- 用户点击删除后，后台重新从站点完整资格列表和**全部选中的下载器**核验名称、大小、具体 Tracker、下载器及哈希，然后才向对应下载器发送一次删除请求。任意下载器离线或数据不完整则拒绝删除；删除后仍以目标哈希从下载器消失为成功依据。
- 仅影响管理页面的**人工确认删除**，不更改自动优选和自动清理策略。删除会同时清理下载器文件，无法由插件撤销，建议在确认新版本正常显示后谨慎操作。

本次按示例名称和模拟下载器进行回归测试，尚未对真实 Transmission 执行删除。`release=false` 继续保留。
