# 不可躺自动抽奖

MoviePilot V3 插件，对应不可躺（外号“躺平”）的 `https://www.tangpt.top/omnibot_lottery.php`。定时任务在 MP 后台执行，不依赖打开网页或油猴。

## 安装与设置

1. MP 第三方插件市场添加 `https://github.com/xchenya/MoviePilot-Plugins`，刷新市场后安装 **不可躺自动抽奖**。
2. 在站点管理维护不可躺的 HTTPS 地址、Cookie 与 User-Agent。插件优先读取 `www.tangpt.top` 的非空 Cookie，再读取 `tangpt.top`；实际请求固定发往 `https://www.tangpt.top`。也可以在“站点连接”填写手动 Cookie 和 User-Agent，手动 Cookie 优先使用，留空则自动读取站点管理。手动配置不要求已添加站点。
3. 首次勾选 **仅检查连接** 后保存，查看详情页结果。该开关独立运行并自动复位，不需要同时开启每日定时或运行一次。检查结果会标注凭据来源与页面解析方式。
4. 设置目标和预算后开启 **启用每日定时**。通知使用 MP 的 **插件** 通知类型，请配置对应渠道。

| 设置 | 默认值 | 说明 |
|---|---|---|
| 每日定时 | 关闭 | 配置完成后手动开启 |
| Cron | `0 8 * * *` | 北京时间每天 08:00；支持 `0 8,18 * * *` 等多次定时 |
| 每日目标 | 10 抽 | 插件北京时间当日的提交上限，1–1000；不按 Cron 触发次数追加 |
| 优先连抽 | 10 抽 | 支持页面的 1 / 10 / 20 / 50 / 100 档位，按额度与余额缩小 |
| 保留魔力 | 100,000 | 按扣费前余额检查，不预支中奖奖励 |
| 单抽费用上限 | 20,000 | 读取的站点单抽价超过此值则停止 |
| 批次间隔 | 30 秒 | 可设 5–900 秒；每批前检查一次页面，不轮询统计接口 |
| 结果通知 | 开启 | 每轮一条汇总：次数、奖品、支出、折算、余额变化及停止原因 |
| 手动 Cookie / User-Agent | 留空 | 可使用其他正常运行插件的同一组凭据；UA 留空时采用站点 UA 或内置完整浏览器 UA |

2026-10-20 当前页面单抽费用为 **20,000 魔力**，单次最多 100 抽。默认 10 抽需支付 200,000 魔力，奖励另计。站点参数会变化，插件每批重新读取实际费用、活动开关、最大连抽数、余额、账号及剩余次数。

## 每日目标与统计

- 以北京时间自然日统计**插件自身**的每日目标和奖品。页面未明确给出站点重置时区或每日总上限，插件不臆测；实际提交同时受页面 `dailyDrawRemaining` 限制。
- 网页手动抽奖只会影响站点剩余次数，不补录到本插件目标和奖品。不要同时运行多个客户端或同账号的多个插件实例。
- 详情页提供今日抽奖次数、奖品分类及次数、消耗、折算与余额变化，保留最近 60 天每日记录和 60 次执行记录，按账号隔离。打开详情页不会访问站点。
- “余额变化”是每批回执余额减提交前余额，可能包含期间做种收入；不是保证收益，也不会把上传量、VIP 或勋章按理论价格算成魔力。
- 未确认请求仍保守占用当天目标，但不会伪造奖品、支出或成功次数。页面明确区分“目标占用”与“已确认”。

## 超时、重启与停止

页面前端使用 `POST /web/omnibot/lottery/draw`，表单字段仅 `count`，未观察到幂等订单号。因此插件**不自动重试抽奖 POST**，包括超时、连接中断、重定向、HTTP 错误和无效回执。

提交前先将账号、日期、数量、费用和余额原子写入插件数据目录。成功回执与清除待核对标记在同一次原子写入中完成。结果不明或进程在中途重启时，所有后续抽奖暂停，定时任务也不会再次请求站点。可独立使用连接检查读取状态。

核对站点后，勾选 **已核对站点结果，解除抽奖暂停** 并保存。这次只解除暂停，不抽奖；原请求仍保守占用其提交日的目标。若已确认失败，可能少抽几次，避免不确定时重复扣费。该操作必须使用原账号；与运行一次同时勾选也不会抽奖。

停用或保存新配置会打断批次等待；已在途请求等待返回后仍保存成功回执。连接超时 10 秒、读取页面超时 30 秒、抽奖回执超时 60 秒。同实例通过线程锁和文件锁防止并发或热重载重叠；不承诺跨机器、跨实例与其他客户端互斥。

自动读取的 Cookie 不回填插件配置。手动填写的 Cookie 作为插件配置保存在 MP 中，输入框以密码样式显示；Cookie 与 User-Agent 均不输出到日志、统计或通知。固定 HTTPS 源、TLS 校验开启、不跟随重定向，复用 Session 接收响应 Cookie。默认不使用代理，可显式开启 MP 系统代理。

## 1.1.0 连接兼容与布局调整

参考 [jiangbkvir 的 tanglottery](https://github.com/jiangbkvir/MoviePilot-Plugins/tree/main/plugins.v2/tanglottery) 的站点 Cookie 选择顺序、文档 GET / AJAX POST 请求方式、页面文字标签及 `ok` 回执字段。网页 GET 不再携带抽奖接口的 AJAX 请求头，POST 使用实际接口的表单类型、Origin、Referer 与 X-Requested-With。

旧版只读取 `mybonus.php` 链接后的直接文本，余额在嵌套标签或链接内部时，会将解析失败误报为 Cookie 问题。新版先识别“当前魔力”及登录栏文字，再兼容链接内外的余额；缺少内嵌状态时，尝试读取页面明确标注的费用、剩余次数和抽奖按钮。无法确认账号、费用、余额或剩余次数时停止抽奖，并报告缺失字段，不猜测每日总额度。内嵌状态存在但无效时不会使用文字覆盖它。

诊断区分登录表单／登录跳转、HTTP 401、HTTP 403、浏览器验证、TLS／网络故障和页面解析失败。仅记录凭据来源、HTTP 状态、响应大小及固定诊断信息，不记录原始响应或认证信息。

配置分为“站点连接”“定时与通知”“抽奖策略”“手动运行与恢复”。输入框、Cron 与说明均置于独立网格行，开关说明使用自动换行文本，避免持久提示与下一行重叠；窄屏自动改为单列。

更新会保留原配置、每日统计与待核对记录。更新后先执行一次连接检查；若自动读取的凭据与正常工作的插件不同，可手动填写同一组 Cookie / UA 后重新检查。连接检查不会消耗魔力。

## 验证范围

已只读核对当前页面的 `window.qqbotLotteryState`、登录栏、抽奖按钮及前端请求／回执字段。此次开发没有发起真实抽奖，没有消耗账号魔力。回执测试使用按前端字段构造的模拟数据，**尚未完成真实 MP 宿主安装和站点抽奖联调**。

离线测试覆盖不同 HTML 余额布局、凭据优先级、请求头、状态与错误分类，以及余额／费用限制、每日目标、重复执行、持久化失败、超时后不重试、重启恢复、一次性开关、取消／重载、账号变化、统计及通知失败。无额外 Python 依赖，无前端构建产物；`release: false` 表示源码分发，不代表市场禁用。
