# PTLGS 幸运大转盘

适用于 MoviePilot V3。根据用户提供的油猴脚本 **PTLGS幸运大转盘 · 自动抽奖 1.8.0** 及 2026-10-20 当前页面协议重新实现 Python 后台任务，不依赖浏览器、油猴或打开插件页面。

## 使用

1. 在 MP 第三方插件市场添加 `https://github.com/xchenya/MoviePilot-Plugins`，安装 **PTLGS 幸运大转盘**。
2. 在 MP 站点管理中添加 `https://ptlgs.org`，维护登录 Cookie 和 User-Agent。
3. 首次只需勾选 **仅检查连接（一次性）**，保存后自动检查一次并复位，无需同时开启其他运行开关。检查失败也不会自动重复执行。
4. 检查成功后开启 **启用每日定时**，设置每日目标后保存。连接检查不会改变后续定时抽奖；若同时勾选“保存后运行一次”，本次只检查连接。
5. 通知通过 MP 的“插件”通知类型发送，请在 MP 中配置通知渠道。

| 设置 | 默认 | 含义 |
|---|---|---|
| Cron | `5 8 * * *` | 每天 08:05 |
| 时区 | `Asia/Shanghai` | 独立于宿主时区，可修改 |
| 每日目标 | 50 抽 | 实际次数，十连抽计 10 次；包括网页手动抽奖 |
| 优先连抽 | 10 | 自动用三连、单抽补足尾数 |
| 保留工分 | 10,000 | 按扣费前余额判断，不预支可能抽中的奖励 |
| 间隔 | 35 秒 | 每批之间的间隔，可设置 3–900 秒 |
| 异常重试 | 3 次 | 除首次请求之外的上限；始终复用同一订单号和数量 |
| 每日定时 | 关闭 | 用户配置完成后开启 |
| 结果通知 | 开启 | 每轮一次汇总，包含异常或提前停止原因 |

当前站点每抽 1,000 工分，每日上限 500 次；插件每次执行从页面读取实际消耗和配额。默认 50 抽最多扣费 50,000 工分，500 抽最多扣费 500,000 工分（未扣除返还奖励）。站点每天 **00:00 UTC，即北京时间 08:00** 重置。多次 Cron 例如 `5 8,12,18 * * *` 只补足每日目标，不按触发次数追加配额。

## 结果与异常处理

- 详情页按站点 UTC 日期显示 **当日累计抽奖次数、奖品及各奖品次数、消耗工分、工分变化、站点剩余次数**。北京时间每天 08:00 切换新一天，同日多次执行累计，连接检查和未发生抽奖的执行不会覆盖当日统计。
- 每日次数与奖品仅包含本插件已确认的订单；网页手动抽奖计入站点配额和每日目标，但不补录奖品。剩余次数是最近一次读取值，跨日后显示“待检查”。
- 历史区包含今天，今天标注“今日”，按日期倒序展开每日汇总及原始命中明细，并显示最近 15 次运行记录；保留 60 次执行记录及 60 天每日统计。按账号隔离，升级保留已有统计；旧数据含多个账号时先检查连接确认当前账号。
- 每次创建新订单前重新读取页面，检查账号、余额、每日配额和活动开关。
- 发请求前原子落盘 `request_key`、数量、账号、日期和扣费前余额。重启、配置变更与超时后优先核对原订单，成功记录与待确认订单清除在同一次原子写入中完成。
- HTTP 429、临时错误及网络异常有限退避，默认 35 / 70 / 140 秒；尊重更长的数字 `Retry-After`，超过 300 秒则结束本轮。登录拒绝和确定业务拒绝直接结束，不无限重试。
- 同一订单只在创建后 15 分钟且同一 UTC 日内自动重试。页面没有公开幂等键保留期限，因此更久或跨日后不自动重放。请到站点核对记录后勾选 **已核对站点，清除待确认订单**；该操作本轮只清标记，不抽奖、不清每日计数。
- 配置变更/停用会打断等待；已在途的请求最多等待连接/读取超时（10/30 秒），收到成功结果仍先记录。
- 线程锁与插件数据目录中的文件锁防止同一实例并发和热重载重叠；**同一账号只启用一个实例，并关闭原油猴脚本**。其他客户端同时抽奖无法被本插件跨客户端锁住。
- Cookie 仅从站点管理读取，只发往固定 HTTPS PTLGS 源，不跟随重定向，默认验证 TLS。日志、状态与通知不存储 Cookie 或 CSRF。
- 工分变化是每笔订单余额差，可能混入期间做种收入；不会按“工分1000”等奖品名称推算实际奖励，避免站点税率/补偿造成误报。

## 奖品汇总与重复折算

- 上传量、下载量分别合计容量，VIP 合计天数，其余奖品分行显示。例如上传 1G ×61 和上传 5G ×30 合并为 **上传 +211 GB**。
- 工分优先采用回执明确给出的 `bonus_gained`。旧记录或未提供该字段的连抽使用 **工分回流（余额口径）= 订单后余额 − 订单前余额 + 本单消耗**，可能包含期间做种收入或其他收支，不将奖品名称直接乘次数冒充实际到账。已经折算的工分包含在合计中，不重复相加。
- 默认开启 **自动识别已拥有奖品**：每轮实际需要抽奖时，只读一次当前账号个人资料、勋章首页和头像框首页，不翻页、不重试、不在每批抽奖时重复读取；之后重新核对抽奖页的账号和配额。仅检查连接、已达每日目标、余额不足时不读取这些参考页。
- 个人资料中明确列出的到期时间决定是否仍持有，商店的“仅授予”“销售已结束”和是否佩戴不代表持有状态。勋章/头像框目录只用来读取抽奖同款的当前价格。
- 配置中提供三项“已拥有”多选作为识别不到时的补充：**二周年限定勋章（抽奖）**、**二周年限定-头像框（抽奖）**、**黑丝娘☆卡牌**。手动勾选黑丝娘需填写北京时间的到期时间；开启自动识别时可留空，依赖站点信息。不要选择价格 500,000 的普通二周年勋章来代替抽奖版。
- 重复持有按同款价格的 50% 折算，每次四舍五入到 1 位小数。2026-10-20 已核对的价格分别为 50,000 / 25,000 / 100，对应折算 25,000 / 12,500 / 50 工分；目录暂不可读时使用这些参考价并标“约”。单抽回执明确返回实际折算金额时以回执为准。
- 未持有时，第一份作为新奖品、同批后续重复份数计折算。新获得状态按账号保存，黑丝娘按 7 天记有效期；重复折算不延长已有有效期。无法确认持有状态时保留原始命中，不把不确定的奖品冒充折算成功。
- 原订单在首次提交前保存当时的持有状态及价格，超时重试沿用原记录；修改配置不会重复统计，也不会用今天的持有状态改写旧记录。旧版历史仍能合并容量和工分回流，但不追溯猜测各件奖品当时是否重复。
